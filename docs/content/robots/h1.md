# Unitree H1 adaptation

The H1 repository stays close to the template's single-state execution model but adds H1-specific state estimation and policies.

## State and control flow

Only `H1RLQPController_Initial` is built. It starts the RL runner immediately:

```text
controller startup
  -> datastore ControlMode = Torque
  -> H1RLQPController_Initial
  -> policy inference and torque-task target updates
```

There is no separate stable posture state or runtime position-to-torque transition in the supplied version.

## Main controller differences

### Contact anchor callback

`initializeRobotBasics()` registers `anchorFrameFunction` in the datastore. The callback invokes `createContactAnchor(real_robot)` and is consumed by the Tilt observer. This is H1-specific integration code, not a generic utility.

### Observer pipeline

H1 adds:

- Encoder observer with encoder velocities;
- `FloatingBase` BodySensor update;
- required Tilt observer using `anchorFrameFunction`;
- momentum-based external-force observer using commanded torque.

### Policies and conventions

The template examples are replaced by H1 standing and walking policies, H1 joint groups, and `pelvis` as base body. The configured default is `standing_h1`.

### Limit monitoring

H1 `computeLimits()` reads the measured robot through `realRobot(robotName_)`, unlike the template implementation that reads the control robot.

## Shared behavior with the template

H1 still starts in torque control, uses one RL-running state, calls `ClosedLoopIntegrateReal`, supports direct torque bypass, and retains the shared policy/runtime architecture.
